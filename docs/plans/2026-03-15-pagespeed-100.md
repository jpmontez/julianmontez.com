## Failing Diagnostics

### 1. LCP Request Discovery (FAIL)

**Symptom:** PSI reports `fetchpriority=high` should be applied to the LCP `<img>` element (`2026-02-21-DSC_0398`), but it is missing.

**Root cause:** `select_lcp_meta()` in `blog/images.py` ranks images by portrait ratio (`height / width`). For the February post with two images (DSC_0398 and DSC_0391), DSC_0391 has a higher portrait ratio and is selected as the predicted LCP. But the actual browser LCP is DSC_0398 — it appears **first in the DOM** (slide 0) and is the first visible element Lighthouse measures.

Because the wrong image is selected:
- DSC_0398 gets `loading="eager"` but **no** `fetchpriority="high"` — PSI flags this
- DSC_0391 gets `fetchpriority="high"` — wasted on a non-LCP image
- The `<head>` preload points to DSC_0391's JPEG srcset — wrong image, wrong format

**Fix — `blog/images.py`:**
Change `select_lcp_meta` to prefer the **first** candidate image instead of the most portrait one. The first image in the DOM is always the LCP candidate for above-fold content; the portrait-ratio heuristic is a bad predictor for horizontally-arranged slideshows.

```python
# Current (incorrect)
return max(enumerate(candidates), key=lambda item: (image_lcp_score(item[1]), item[0]))[1]

# Proposed
return candidates[0]  # First DOM element is the actual LCP
```

### 2. Improve Image Delivery — AVIF Preload Format Mismatch (FAIL)

**Symptom:** PSI estimates 526 KiB savings on mobile (166 KiB on desktop). Two sub-issues:

**Sub-issue A — Preload uses JPEG, browser downloads AVIF:**
The `<link rel="preload">` in `<head>` is generated with the native (JPEG) srcset:
```html
<link rel="preload" as="image"
  href="./static/...1080w.jpg"         ← JPEG
  imagesrcset="...480w.jpg 720w.jpg…"  ← JPEG srcset
  fetchpriority="high" />
```
Modern browsers that support AVIF download the AVIF variant from the `<source type="image/avif">` element. The JPEG preload is a wasted download — the browser fetches the JPEG speculatively, then discards it when it encounters the `<picture>` and picks AVIF instead. This delays the actual LCP resource.

**Sub-issue B — AVIF quality too low (files too large):**
AVIF variants are generated at `quality=55` (`blog/images.py` line 224). PSI explicitly recommends increasing the compression factor. Reducing to ~40 can cut file sizes by 30–40% with minimal perceptual quality loss at the display sizes used here (≤520 px on desktop, 100vw on mobile).

**Fix A — `blog/models.py` + `blog/render.py` + `blog/templates/base.html`:**
Update `PreloadImage` to carry the AVIF srcset alongside the native srcset. In `base.html`, emit an AVIF preload with `type="image/avif"` (browsers that don't support AVIF simply ignore it), and keep the JPEG preload as a fallback.

```python
# models.py — add avif_srcset to PreloadImage
@dataclass(frozen=True)
class PreloadImage:
    src: str
    srcset: list[tuple[str, int]]
    avif_srcset: list[tuple[str, int]] = field(default_factory=list)
```

```python
# render.py — pass avif_srcset
PreloadImage(
    src=image_src(lcp_meta),
    srcset=lcp_meta.srcset,
    avif_srcset=lcp_meta.avif_srcset,
)
```

```html
<!-- base.html — emit AVIF preload first, JPEG as fallback -->
{% if preload_image.avif_srcset %}
<link rel="preload" as="image" type="image/avif"
  href="{{ assets_prefix }}/{{ preload_image.src | replace('.jpg', '.avif') }}"
  imagesrcset="{% for v, w in preload_image.avif_srcset %}{{ assets_prefix }}/{{ v }} {{ w }}w{% if not loop.last %}, {% endif %}{% endfor %}"
  imagesizes="{{ image_sizes }}"
  fetchpriority="high" />
{% endif %}
<link rel="preload" as="image"
  href="{{ assets_prefix }}/{{ preload_image.src }}"
  fetchpriority="high"
  {% if preload_image.srcset %}
  imagesrcset="{% for v, w in preload_image.srcset %}{{ assets_prefix }}/{{ v }} {{ w }}w{% if not loop.last %}, {% endif %}{% endfor %}"
  imagesizes="{{ image_sizes }}"
  {% endif %} />
```

**Fix B — `blog/images.py` line 224:**
```python
# Current
save_kwargs={"quality": 55},

# Proposed
save_kwargs={"quality": 40},
```
After changing this, delete `blog/.image-manifest.json` so all AVIF variants are regenerated.

Steps are ordered by impact. Complete each in sequence; run tests after each step.

### Step 1 — Fix LCP image selection

**File:** `blog/images.py`

**Why:** Ensures `fetchpriority="high"` and the `<head>` preload are placed on the correct image (first in DOM = actual LCP element).

**Files:** `blog/models.py`, `blog/render.py`, `blog/templates/base.html`
**Change:** Add `avif_srcset` to `PreloadImage`; emit AVIF preload with `type="image/avif"` in `<head>`.
**Why:** AVIF-capable browsers (Chrome, Firefox, Safari since 2022 = ~90%+ of traffic) will now get an early preload hint for the resource they'll actually download.
**Test:** Inspect `dist/index.html` `<head>` — confirm AVIF preload is present with correct AVIF srcset. Confirm no layout regression.

**File:** `blog/images.py` line 224

**Why:** PSI explicitly recommends more compression. Quality 40 in Pillow's AVIF encoder produces excellent visual quality at display sizes ≤ 1080 px, with ~30–40% smaller files.
**Side effect:** All AVIF files must be regenerated — delete `blog/.image-manifest.json` before rebuilding.
**Test:** Visual inspection of generated images at 100% zoom. Run PSI again; expect "Improve image delivery" savings to drop significantly.
